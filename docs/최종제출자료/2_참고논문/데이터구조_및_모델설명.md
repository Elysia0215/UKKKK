# 서울시 출산정책 제안 데이터 분류/담당매칭 데이터 구조

## 1. 입력 파일

### 제안 데이터
- 파일: `서울시_출산정책_제안데이터_426건_2026-07-21.csv`
- 단위: 시민 제안 1건 = 1행
- 주요 원본 컬럼: 제안ID, 카테고리, 제안제목, 제안본문내용, 등록일자, 공감수, 댓글수, 답변여부, 자치구, 담당부서, 원문URL, 연동 권익위 민원수

### 업무담당 데이터
- 파일: `출산정책관련 업무담당.xlsx`
- 단위: 업무담당자/담당업무 1건 = 1행
- 주요 컬럼: 담당부서, 직원명, 전화번호, 담당업무, 부서위치

## 2. 추가 생성 컬럼

| 컬럼명 | 의미 |
|---|---|
| 대분류 | 제안의 정책 영역 1차 분류 |
| 중분류 | 실제 사업/업무 단위에 가까운 2차 분류 |
| 세분류 | 제안 내용을 더 구체화한 3차 라벨 |
| 정책흐름 | 임신 전, 임신 중, 출산 직후, 영유아/초등 양육기 등 생애주기 흐름 |
| 분류근거_키워드 | 분류에 사용된 핵심 키워드 |

## 3. 분류 체계

대분류는 다음 8개로 구성했다.

1. 임신·난임·생식건강
2. 출산·산후 초기지원
3. 보육·돌봄 인프라
4. 다자녀·양육비·생활지원
5. 주거·교통·도시생활환경
6. 일·가정 양립·부모 노동
7. 취약·다양가족 사각지대
8. 정보·상담·교육·거버넌스

## 4. 사용 모델/방법론

이번 파일 생성에는 KMeans, LLM, 딥러닝 모델을 사용하지 않았다.

사용 방식은 **규칙 기반 키워드 점수화(rule-based keyword scoring)** 이다.

### 이유
- 담당부서 매칭은 “왜 이 부서/담당자인지” 설명 가능해야 한다.
- KMeans는 비지도 군집이라 군집번호가 자동으로 생성되고, 업무담당자 1·2·3순위 라우팅 근거를 설명하기 어렵다.
- 따라서 실제 업무분장 텍스트와 제안 텍스트의 키워드 연결성을 점수화했다.

## 5. 담당자 매칭 로직

담당 매칭 점수는 다음 요소를 합산했다.

1. 제안 제목/본문의 핵심 키워드
2. 기존 카테고리/담당부서 힌트
3. 새로 만든 대분류/중분류/세분류
4. 업무담당 파일의 담당업무 텍스트
5. 수작업으로 정의한 담당업무 핵심 키워드
6. 대분류/중분류별 관련 전화번호 부스트

점수가 높은 순서대로 1순위, 2순위, 3순위 담당 후보를 산출했다.

## 🧠 UKKKK 코드 검증 7대 핵심 기술 하이브리드 파이프라인

본 프로젝트(UKKKK)는 팩트에 근거하여 **KR-SBERT 문장 임베딩**과 **계층적 군집화**로 의미가 유사한 제안을 묶고, **TF-IDF**로 핵심 키워드를 추출합니다. 정책 분류와 담당팀 후보 추천에는 **설명 가능한 규칙 엔진**을 적용하고, **MCDA 다기준 가중치 모델**로 검토 우선순위를 산정하며, **Gemini 2.5 Flash**가 담당자가 검토·수정할 행정 답변 초안을 생성하는 **7대 핵심 기술 결합 하이브리드 파이프라인**입니다.

---

## ⚙️ 7대 핵심 기술 / 알고리즘 풀 라인업 (Code-Verified)

| 번호 | 기술 구분 | 핵심 기술 / 알고리즘 | 실제 코드 작동 역할 및 검증 명세 |
| :---: | :---: | :--- | :--- |
| **01** | **딥러닝 (DL)** | **`KR-SBERT`** (`snunlp/KR-SBERT-V40K-klueNLI-augSTS`) | 824건 제안 & 582건 민원 비정형 텍스트의 **768차원 문장 밀집 임베딩·의미 분류** |
| **02** | **머신러닝 (ML)** | **`계층적 군집화`** (`Agglomerative Clustering`) | 코사인 거리 기준 유사 제안 및 고충을 **57개 문제 군집(Cluster)으로 형성** |
| **03** | **수학 / 통계** | **`코사인 유사도`** (`Cosine Similarity`) | 문장 임베딩 벡터와 정책 분류 설명 간의 **의미적 유사도/거리 정밀 계산** |
| **04** | **생성형 AI (LLM)**| **`Gemini 2.5 Flash`** (`gemini-2.5-flash`) | 1클릭 행정 공문 초안 자동 생성 (담당자가 직접 검토·수정·승인하는 구조) |
| **05** | **NLP / 통계** | **`TF-IDF`** (직접 계산 정규화) | 프런트엔드에서 TF·DF·IDF 직접 산출 기반 **TOP 30 핵심 키워드 중요도 파싱** |
| **06** | **다기준 평가** | **`MCDA 가중합`** (Multi-Criteria Analysis) | 수요·공백·시급성·실행가능성·신뢰도 5축 가중합 기반 **우선순위 투명 산정** |
| **07** | **규칙 엔진 (Rule)**| **`Regex · 행정 규칙 엔진`** | `AMBIGUOUS_DISTRICT_KEYWORDS` 자치구 중의어 방지, 11개 팀 R&R 라우팅 |

> 📌 **NMF 토픽 분석 산출물 연계:** 기존에 생성된 토픽별 키워드 결과를 뉴스 분류 규칙에 활용했으며, 현 저장소에는 NMF 재학습 코드가 포함되어 있지 않고 사전 산출 데이터를 연계함.

--- 6. 해석 주의사항

이 결과는 최종 행정 배정이 아니라, 대시보드/기획안용 **1차 라우팅 후보**이다. 특히 분류신뢰도가 낮거나 매칭근거 점수가 낮은 행은 사람이 최종 검토해야 한다.
